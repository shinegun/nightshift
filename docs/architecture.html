How the backend actually works

One Node process, two ports, a 30-second heartbeat, and a tool-using agent loop in the middle. Everything below is read off the code as it stands today, including the parts that aren't finished.

01Two doors, one locked

The same process listens twice. Port 4455 is the dashboard and its API: everything that can spend money, send mail, or read the inbox. Port 4456 is the surface that deployed websites talk to, and it is deliberately tiny — three route groups, no authentication, because a visitor's browser has no credentials to offer.

02The heartbeat

Nothing is event-driven. A setInterval fires every 30 seconds and walks the same short list, and a second one syncs integrations every 5 minutes. The budget is checked on three different edges here, and the morning report is deliberately not one of them — it is how you find out the day stopped.

03The agent loop, and the step that isn't there

This is the core. A task becomes a conversation: system prompt, the task, then up to 25 rounds of model reply → tool calls → results fed back. Every model call passes through llm.ts, which is where the budget can stop it mid-task, and where the conversation now gets saved so the retry resumes instead of paying twice.

The loop has no step that checks whether the work is any good. SafaStack ships a test suite, a copy check and a schema validator; the agent that edits SafaStack has never run one of them.

04Two paths out, joined by a human

This is the part that matters most before a second person starts committing. The live site does not come from GitHub. Nightshift uploads the site folder straight to Vercel, and the repo exists alongside it for the tooling and the nightly ingest. Nothing pulls one into the other.

06What this map says is missing

  • No check

    Nothing verifies an agent's work before the task is filed. The project's own tests exist and are never run. Fixing this is what would let the morning report shrink to something worth trusting.

  • No git

    Agents cannot commit, push, or open a pull request, so finished work waits on you to type the command. Several open requests are exactly that chore.

  • No trimming

    A task's conversation only grows. One task spent 2.59M prompt tokens across 25 calls, and cost inside a run climbs faster than the work does.

  • Exposed

    The dashboard port binds every interface. It should bind localhost and reach you over the tailnet instead.
